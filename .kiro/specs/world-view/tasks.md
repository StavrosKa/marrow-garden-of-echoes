# Implementation Plan

## Overview

This plan builds the world-view spec in eight tasks. Each task is one commit and starts from finished, tested work. Requirement numbers refer to `requirements.md`; section numbers refer to `design.md` (both final at `f2754f0`; this plan does not change them).

Rules for every task:

- A task is done only when `npm run typecheck`, `npm run lint` and `npm test` pass, plus `npm run test:e2e` for tasks 7 and 8. Each task repeats its own line.
- Each logic task has its property tests in the same task. Test titles are the literal names of design §9.1 and §9.2. A test that has no literal name there gets a title that starts with the criterion ids it covers (for example `12.1 12.2: placement of both stops`), and the coverage table of task 8 uses those titles as written.
- Tests read numbers from `TUNING` (world-view) or marrow's `TUNING`, never from literals. The only literals allowed in a test are the ones that define a level or a table row in the requirements (for example the Full and Reduced head multipliers 1 and 0 in the motion-profile table) and the test parameters of design §5.1. A failing fast-check seed becomes a regression test and a row in `docs/bugs-found.md` (real bugs only: seed, what broke, regression test, fix commit by subject line).
- Each core task adds its public names to the `world-view` entry (design §1.3). Internals (`smootherstep`, `layerTransform`, `maxParallaxShift`, `motionRank`, `testgen`) stay off it.
- No lint exception, no weakened rule in `eslint.config.js` or `tests/dependency-graph.test.ts`, and no dependency beyond `pixi.js` 8.22.0. A change to either file may only add coverage.
- Mutation check: only for the eight named property tests, 3-5 mutations per property, at most 10 per task, as one script run with `powershell -File` from `.scratch`, with copies of each mutated file in `.scratch` and the SHA-256 of every mutated file compared with the original at the end. Rerun only a survivor's mutation, once. No mutations for UI, slice wiring, copy or documents. The scripts and copies in `.scratch` are deleted when the task is done.
- Stop and ask instead of choosing, if a task needs: a change to `requirements.md` or `design.md`; a new key in `tuning.ts` that design §5.1 does not list; a new dependency; a lint or dependency-graph exception; or a change to `playwright.config.ts`.
- Every task ends with a journal entry in `docs/kiro-journal.md` (facts only, real command output, one thing that needed correcting and how, the commit cited by subject line), then commit and push. If the push is rejected, stop and report; never force-push.
